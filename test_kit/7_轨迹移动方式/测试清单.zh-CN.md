# 轨迹移动方式（直線移動 / 直線移動(時間制御)）实机测试清单

这份清单要回答两件事：

1. 「直線移動(時間制御)」在**不编辑曲线**的时候，和「直線移動」逐帧是不是一样的？中间点（多段往返）的情况下也一样吗？
2. 自定义曲线（在「時間制御編集」里画出来的缓动）在 `.aup2` 工程文件里是怎么写的？

工程都是单场景、30fps、5 秒、白色圆（X 轨迹）。圆的起点和终点都在画面里水平移动。

---

## 〇、文件一览

所有工程都在本文件夹里（`D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\`）。

| 文件 | 帧率 | X 轨迹 | 中间点 | 说明 |
|---|---|---|---|---|
| `R1a_直線移動.aup2` | 30 | 直線移動 | 无（起点→终点） | 基准 |
| `R1b_直線移動時間制御.aup2` | 30 | 直線移動(時間制御) | 无 | 不编辑曲线，应与 R1a 逐帧相同 |
| `R1c_中間点_直線移動.aup2` | 30 | 直線移動 | frame=0,50,100,149，往返 3 段 | 基准 |
| `R1d_中間点_直線移動時間制御.aup2` | 30 | 直線移動(時間制御) | frame=0,50,100,149，往返 3 段 | 不编辑曲线，应与 R1c 逐帧相同 |
| `R2_曲线底稿.aup2` | 30 | 直線移動(時間制御)，曲线待你来画 | - | 底稿，**不要覆盖**，只能「名前を付けて保存」 |

说明：

- R1a 与 R1b、R1c 与 R1d 之间只差「移動方式」这一项，其它都一样。
- R1d 的中间点如果被忽略，R1d 会变成一段直线（失去往返），这是要观察的结果，**如实记录，不要为了让它「通过」去改文件**。

## 一、准备

1. 确认 AviUtl2 是 v2.1.12（与其它清单一样）。
2. 确认 `D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\` 文件夹存在。不存在就新建一个空文件夹。
3. 确认 `D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\截图\` 文件夹存在。不存在就新建。截图都存这里。
4. 分析工具：Python 要能运行（`python -I` 能跑），ffmpeg / ffprobe 要在 PATH 里（命令行里 `where ffmpeg` 能找到）。
5. 整个测试**不要 commit，不要改任何 `.aup2` 工程文件**（R2 的另存除外）。

## 二、预览检查（四个 R1 工程都要做）

1. 用 AviUtl2 打开 `R1a_直線移動.aup2`。
2. 拖动时间轴或按播放，看白色圆是否从左向右（或按设定方向）移动。
3. 记下三件事：
   - 圆是不是在动，起点和终点是否合理；
   - R1c / R1d 的圆是不是往返了（起点 → 中间 → 回来 → 终点，共 3 段）；
   - 有没有卡顿、跳变。
4. 对 `R1b`、`R1d` 重复上面的步骤。
5. 如果某个工程打不开，或者圆不动、或者「移動方式」显示不对：
   - 截图存到 `截图\`，文件名写清楚（例如 `截图\R1d_打开失败.png`）；
   - 在回报里写清楚现象；
   - **不要自己乱改文件**。

## 四、分析（每个 mp4 运行一次）

在命令行里逐个运行下面的命令（完整路径，不依赖当前目录）。每条命令的输出都要完整保存。

R1a 和 R1b、R1c 和 R1d 各自要分别导出 CSV，便于后面逐帧对比。

```
python -I "D:\AviUtl Free Render FPS\experiments\subscene_rate\analyze_steps.py" "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1a.mp4" --csv "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1a.csv"
python -I "D:\AviUtl Free Render FPS\experiments\subscene_rate\analyze_steps.py" "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1b.mp4" --csv "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1b.csv"
python -I "D:\AviUtl Free Render FPS\experiments\subscene_rate\analyze_steps.py" "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1c.mp4" --csv "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1c.csv"
python -I "D:\AviUtl Free Render FPS\experiments\subscene_rate\analyze_steps.py" "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1d.mp4" --csv "D:\AviUtl Free Render FPS\test_kit\7_轨迹移动方式\out\R1d.csv"
```

需要回报的内容（每个文件）：

- 输出里的段数、「段长分布（长度: 段数）」那一行；
- 前 10 段的「帧范围」和「长度」；
- 如果输出里有「质心 x (px)」一列，记下前 10 段的值。

预期：

- **R1a 与 R1b 逐帧相同**：两个 CSV 的每一行（每一帧的位置）数值一样。
- **R1c 与 R1d 逐帧相同**：两个 CSV 的每一行数值一样。
- 如果 R1d 的中间点时间被忽略，R1d 会变成一段直线，与 R1c 不同。这是要观察的结果，**照实记录**，不要当成失败去改工程。

逐帧对比的做法（任选一种）：

- 用 Excel / 记事本直接打开两个 CSV 对照前几行和中间几行；
- 或者在 PowerShell 里运行 `Compare-Object (Get-Content R1a.csv) (Get-Content R1b.csv)`，有输出就说明有不同行，没有输出就说明完全相同。

把对比结果（相同 / 不同，不同的话第几行开始不同）写进回报。

## 五、R2：自定义曲线（時間制御編集）

目的：拿到一个**画过曲线**的工程文件，我用它来看自定义曲线在 `.aup2` 里是怎么写的。

1. 打开 `R2_曲线底稿.aup2`。
2. 选中圆，在 X 轨迹的设置图标（齿轮 / 设定按钮）上点一下，打开「時間制御編集」。
3. 画一条明显的缓动曲线，例如：
   - 先慢后快；或者
   - 用预设里的一种（选一个你能说出名字的，把名字写在回报里）。
4. 点「名前を付けて保存」，保存到 `out\R2_曲线.aup2`。
   - **不要覆盖 `R2_曲线底稿.aup2`**。
   - 保存前确认文件名里是 `R2_曲线.aup2`，路径在 `out\` 里。
5. 再普通导出一次（和第三节一样，x264guiEx，**「Enable Free Render FPS」不勾选**），输出为 `out\R2_30.mp4`。
6. 把 `out\R2_曲线.aup2` 发回来。

**如果还有余力**（这一步可以跳过）：

7. 在 `R2_曲线底稿.aup2` 的基础上，画一条**带多个控制点**的曲线（例如 3 个以上的点，有慢有快）。
8. 同样「名前を付けて保存」到 `out\R2_曲线2.aup2`，不要覆盖底稿。
9. 把 `out\R2_曲线2.aup2` 也发回来。

注意：

- 如果曲线编辑器打不开，或者找不到「時間制御編集」入口，截图存到 `截图\`，文件名写清楚，不要改底稿。
- 导出的 mp4 不需要分析，只要能正常打开即可。
