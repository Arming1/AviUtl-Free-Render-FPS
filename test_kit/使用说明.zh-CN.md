# test_kit 使用说明

本文件夹包含两组真机测试所需的工程与素材，打开即可使用，不需要再到仓库里查找。测试对象：AviUtl2 v2.1.12。

## 文件结构

```
test_kit\
  1_精确模式8组\
    60_to_66.aup2  72_to_60.aup2  30_to_5994.aup2  66_to_24.aup2
    66_to_120.aup2 120_to_60.aup2 60_to_50.aup2   72_to_59.aup2
    out\            （8 组导出的视频放在这里）
  2_长视频音画同步\
    long_sync_60fps.aup2
    beeps_30min.wav
    out\            （3 组导出的视频放在这里）
  使用说明.zh-CN.md
```

每个 `.aup2` 都是一次性副本，文件名即用例名。工程里的 `file=` 与 `output.file=` 已指向本文件夹内的绝对路径。工程的帧率与对象没有改动，目标帧率需要在「编辑 > Free FPS Export...」对话框中填写。

## 一、安装插件

本测试使用的插件为 `test_kit\plugin\x264guiEx-FreeRenderFPS.aux2`（ProductVersion 1.1.0，SHA-256 `AD2364469BA91A8B89AAB8F50B2D2958AE211B779AFD11DF5CDA0CB3434CFD3A`）。

1. 关闭 AviUtl2（任务管理器中不能有 `aviutl2.exe`）。
2. 在 `test_kit\plugin\` 中右键「安装.ps1」，选择「使用 PowerShell 运行」；或在 PowerShell 中执行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File "D:\AviUtl Free Render FPS\test_kit\plugin\安装.ps1"
   ```

   脚本会先把 `C:\ProgramData\aviutl2\Plugin\x264guiEx-FreeRenderFPS\x264guiEx-FreeRenderFPS.aux2` 备份为同目录的 `x264guiEx-FreeRenderFPS.aux2.before-precise`（备份已存在时不覆盖并提示），再替换 `.aux2` 本体。`.ini`、`.conf` 等文件不会改动。如果检测到 AviUtl2 正在运行，脚本会提示并退出，不做任何修改。
3. 启动 `D:\aviutl2 v2.1.12\aviutl2.exe`（不要用桌面上指向 beta42 的快捷方式）。
4. 打开「编辑 > Free FPS Export...」，确认对话框中有「Precise motion」复选框。

回退：关闭 AviUtl2 后，在 `test_kit\plugin\` 中运行「回退.ps1」（同样可用 PowerShell 运行），脚本会用 `.aux2.before-precise` 恢复原来的 `.aux2`。

## 二、8 组精确模式导出

操作步骤：

1. 在 AviUtl2 中用「文件 > 開く」打开下表中的工程副本。
2. 「编辑 > Free FPS Export...」中填写下表的「目标帧率」（精确分数直接填写，例如 `60000/1001`）。
3. 「输出文件」填写下表的输出路径（完整路径为 `D:\AviUtl Free Render FPS\test_kit\1_精确模式8组\out\<文件名>`）。
4. 保持 **Precise motion（exact speed for linear motion）** 勾选。
5. 保持 **Enable Free Render FPS** 不勾选（它是输出插件内置开关，本测试只使用 Free FPS Export）。
6. 确认保存工程的提示后开始导出。导出结束后记录实际帧数与时长。

源工程的帧率、帧数均来自 `experiments/free_fps_matrix/cases.json`。预计帧数按 `ceil(源帧数 × 目标帧率 / 源帧率)` 计算，预计时长为 预计帧数 ÷ 目标帧率。

- [ ] 1. `60_to_66.aup2`：源 60 FPS，目标帧率 `66`，输出 `60_to_66.mp4`，预计 330 帧，5 s
- [ ] 2. `72_to_60.aup2`：源 72 FPS，目标帧率 `60`，输出 `72_to_60.mp4`，预计 300 帧，5 s
- [ ] 3. `30_to_5994.aup2`：源 30 FPS，目标帧率 `60000/1001`，输出 `30_to_5994.mp4`，预计 300 帧，1001/200 s（5.005 s）
- [ ] 4. `66_to_24.aup2`：源 66 FPS，目标帧率 `24`，输出 `66_to_24.mp4`，预计 120 帧，5 s
- [ ] 5. `66_to_120.aup2`：源 66 FPS，目标帧率 `120`，输出 `66_to_120.mp4`，预计 600 帧，5 s
- [ ] 6. `120_to_60.aup2`：源 120 FPS，目标帧率 `60`，输出 `120_to_60.mp4`，预计 300 帧，5 s
- [ ] 7. `60_to_50.aup2`：源 60 FPS，目标帧率 `50`，输出 `60_to_50.mp4`，预计 250 帧，5 s
- [ ] 8. `72_to_59.aup2`：源 72 FPS，目标帧率 `59`，输出 `72_to_59.mp4`，预计 295 帧，5 s

注意：每个工程副本只用于对应的一个用例。如果副本已被 AviUtl 保存过，内容可能与最初版本略有不同，但帧率与对象不会改变。

## 三、30 分钟音画同步导出

工程：`2_长视频音画同步\long_sync_60fps.aup2`（60 FPS，108000 帧，即 1800 s；音频 `beeps_30min.wav` 为 30 分钟、48 kHz、单声道，每秒一次嘀声；时间轴上每秒有一个 2 帧的白色闪屏）。

操作步骤与第二节相同，每组导出前在对话框中分别填写下表的目标帧率与输出文件，并保持「Precise motion」勾选、「Enable Free Render FPS」不勾选。

- [ ] 1. 目标帧率 `66`，输出 `D:\AviUtl Free Render FPS\test_kit\2_长视频音画同步\out\long_66.mp4`，预计 118800 帧，1800 s
- [ ] 2. 目标帧率 `50`，输出 `D:\AviUtl Free Render FPS\test_kit\2_长视频音画同步\out\long_50.mp4`，预计 90000 帧，1800 s
- [ ] 3. 目标帧率 `60000/1001`，输出 `D:\AviUtl Free Render FPS\test_kit\2_长视频音画同步\out\long_5994.mp4`，预计 107893 帧，约 1800.015 s

关于是否需要重新复制工程：Free FPS Export 的流程是，每次导出前先把当前工程保存到它自己的路径（`save_project_file`），然后复制到临时目录做重定时，导出完成后再重新打开原工程（`freefps_export.cpp` 文件头注释的第 4 步和第 8 步）。因此三组可以使用同一份 `long_sync_60fps.aup2`，原工程的帧率不会被改变。注意每次导出前工程文件都会被 AviUtl 重新保存。

## 四、分析结果

1. 双击或右键运行 `test_kit\分析\一键分析.ps1`（选择「使用 PowerShell 运行」）。需要 Python 3（含 numpy）。脚本会自动寻找 ffmpeg 与 ffprobe：先找 PATH，找不到时使用固定的 ffmpeg 目录（`D:\FFmpeg-master\...\bin`）；两处都找不到时会给出中文提示并退出。运行开头会打印实际使用的 python、ffmpeg、ffprobe 路径。
2. 脚本会做两件事：
   - 对 `1_精确模式8组\out\` 中的 8 个 mp4，分别按 `precise`、`original`、`retimed` 三种时间轴运行 `experiments\free_fps_matrix\analyze.py`；
   - 对 `2_长视频音画同步\out\` 中的 `long_66.mp4`、`long_50.mp4`、`long_5994.mp4` 运行音画同步分析。
   
   缺失的视频会跳过并在屏幕上提示。
3. 结果全部写在 `test_kit\分析\` 下：`SUMMARY_precise.md`、`SUMMARY_original.md`、`SUMMARY_retimed.md`（以及对应的 `summary_*.json`、`8组_analysis_*\`），长视频结果为 `长视频_66.txt`、`长视频_50.txt`、`长视频_5994.txt`。脚本结束时会打印一张汇总表。
4. 把整个 `test_kit\分析\` 文件夹打包发回。

注意：分析脚本会在 `1_精确模式8组\out\` 下生成 `SUMMARY.md`、`summary.json` 和 `analysis\`，这是正常现象，它们每次运行都会被覆盖，结果已另存到 `test_kit\分析\`。
