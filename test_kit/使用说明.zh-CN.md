# test_kit 使用说明（索引）

test_kit 是 AviUtl2 实机测试用的工程（.aup2）、探针、分析脚本、清单和实测数据。
导出的视频（out\）、插件二进制（plugin\*.aux2）、截图（截图\）和 .wav 不入库，见 `.gitignore` 中的 test_kit 段。
每个子目录的测试内容以它自己的清单与结果文件为准，本文件只做索引。

适用插件版本：**v1.3.0**（宿主：AviUtl2 v2.1.12）。

## 一、安装测试版插件

- 插件二进制不在仓库里。从 Release 下载 `x264guiEx-FreeRenderFPS.aux2`，或本地编译后放入 `test_kit\plugin\`。
- 安装：关闭 AviUtl2，在 `test_kit\plugin\` 中右键「安装.ps1」，选「使用 PowerShell 运行」。
  - 脚本会自动请求管理员权限（UAC 点「是」）。
  - 检测到 `aviutl2` 正在运行时直接退出，不做任何修改。
  - 复制前把原 `.aux2` 备份为 `.aux2.before-precise`；复制后核对安装后的 SHA-256 与源文件一致。
  - 结束时停住，等你按回车关闭。
- 回退：关闭 AviUtl2 后运行「回退.ps1」，用 `.aux2.before-precise` 恢复。
- 哈希不在本文件里记录。以 Release 页面或「安装.ps1」输出的 SHA-256 为准。

## 三、通用分析命令

**单个视频的停留 / 步进检查**：`experiments\subscene_rate\analyze_steps.py`

```powershell
python -I "D:\AviUtl Free Render FPS\experiments\subscene_rate\analyze_steps.py" "<视频.mp4>" [--expect follow|keep] [--step N] [--csv 结果.csv]
```

- `--expect follow`：每帧都动，内部段长应为 1。
- `--expect keep`：子场景保持自己的帧率，内部段长应为 `--step N`（如 60 fps 输出里的 15 fps 子场景用 `--step 4`）。
- 阈值 0.5 px：同一位置的判定（`SAME_EPS_PX`），以及步长一致性容差（`STEP_TOL_PX`，另有相对 2% 的容差）。
- 首尾段不检查段长，可以比内部段短或长（开始或结束时的停留不算失败）。
- 退出码：0 通过，1 失败，2 输入或环境错误。

**批量分析**：`test_kit\分析\一键分析.ps1`（右键「使用 PowerShell 运行」）

- 对 `1_精确模式8组\out\` 的 8 个 mp4 跑 `precise`、`original`、`retimed` 三种时间轴。
- 对 `2_长视频音画同步\out\` 的 long_66 / long_50 / long_5994 跑音画同步分析。
- 需要 Python 3（含 numpy）。ffmpeg / ffprobe 先找 PATH，找不到则用脚本里的固定目录。
- 输出写在 `test_kit\分析\`。

## 四、实测数据进 Actions

- `7_轨迹移动方式\data\*.csv` 与 `8_補間移動時間制御\data\*.csv` 是宿主实测的逐帧质心，入库。
- CI 在 `.github/workflows/ci.yml` 的对应 job 中运行 `python -I tests/host_results/host_results.py`，用这些 CSV 复算，结果写入 Actions 的 summary。
