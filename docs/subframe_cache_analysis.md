# Subframe cache analysis（Phase 5）

## 结论

**任意 subframe 求值可行，但当前输出缓存不能把同一整数帧的 80.0 与 80.5 区分开。**

60 个唯一整数请求 0..59 每次都进入 RVA `0x2662d0`，并按 0.0、0.5、1.0、1.5…求值，产生不同的中间动画状态和图像哈希。相反，对整数帧 80 连续请求三次并计划映射为 80.0、80.5、80.0 时：

- 第一次 80.0：进入状态构造器，应用 double=80.0；
- 第二次 80.5：`func_get_video(80)` 直接返回，状态构造器命中数为 0；
- 第三次 80.0：同样直接返回，状态构造器命中数为 0；
- 三次 RGB 哈希全部是 `875555f88e3def2b`。

这不是“80.5 被求值后画面刚好相同”，而是 80.5 根本没有到达求值入口。

## 实验设计

探针先请求 60 个唯一整数帧并计算完整 1920×1080 RGB 的 FNV-1a 64 位哈希、非黑像素包围盒和质心；代码见 `experiments/subframe_scheduler_test/subframe_scheduler_probe.cpp:44-119,148-168`。然后追加：

```text
func_get_video(80)  -> planned 80.0
func_get_video(80)  -> planned 80.5
func_get_video(80)  -> planned 80.0
```

调度 watcher 在每个公开回调入口创建事务，在回调返回时记录候选命中数；实现见 `subframe_scheduler_watch.cpp:292-335,416-450`。

## 实测证据

`phase5_schedule_watch_final.log:244-253`：

| 请求序号 | 整数请求 | 目标 double | 状态构造命中 | 应用次数 |
|---:|---:|---:|---:|---:|
| 60 | 80 | 80.0 | 1 | 1 |
| 61 | 80 | 80.5 | 0 | 0 |
| 62 | 80 | 80.0 | 0 | 0 |

`phase5_schedule_output_final.log:122-127`：三次最终哈希、包围盒和质心完全相同。

静态分析与这个结果一致但不能单独证明缓存层级：RVA `0x2206B0` 的私有视频工作器接收整数 `R8D`，按整数步进；其下游 RVA `0x2219D0` / `0x221C00` 有 4 字节键哈希、bucket 遍历和引用计数特征。早期记录见 `docs/internal_render_candidates.md:108-115,211-212`。

## 分层判断

| 缓存/系统 | Phase 5 能确认什么 | 不能确认什么 | 风险 |
|---|---|---|---|
| 输出/视频工作器缓存 | 同一 `func_get_video(80)` 的后两次调用绕过时间轴构造；整数请求身份足以命中 | 精确键结构、失效条件和拥有者类型 | **已证实会阻止重复键 subframe** |
| 场景/合成缓存 | 唯一整数请求携带 subframe 时最终合成画面不同 | 是哪一层最终保存 RGB；是否还含场景/对象版本号 | 高 |
| 对象动画缓存 | 唯一请求下 0.5 帧动画正确，说明本测试对象没有把 double 丢掉 | 重复整数键下对象缓存是否也会碰撞；其他对象类型 | 高、未隔离 |
| 效果缓存 | Phase 3 日志滤镜在 60 个唯一样本各收到一次正确 time | GPU/脚本/第三方效果各自的缓存键 | 高、未覆盖 |
| 媒体缓存 | 未使用外部视频/音频素材 | 解码帧、运动补偿、素材时间映射 | 未测试 |
| 预览缓存 | 本实验走输出插件 | 预览刷新/缩略图/编辑器缓存 | 未测试 |
| 音频缓存 | 未请求音频 | 音频采样时间与场景 double 的关系 | 未测试 |

测试工程只有一个程序化白色圆形和一个只记录数据的滤镜，因此不能把“本场景成功”外推为所有对象、效果、媒体和 GPU 缓存都正确。

## 对生产架构的约束

生产方案不能简单重复同一整数 `func_get_video(frame)` 再改全局时间；第二次调用可能在 Hook 前就被缓存吞掉。至少需要以下一种经验证的策略：

1. **唯一任务键：** 每个输出样本使用不会碰撞的内部 render-task/cache identity，同时把场景 double 与该任务绑定；
2. **扩展缓存键：** 在相关缓存键中加入规范化有理采样坐标，例如 `(sample_index, output_rate)`，避免直接用二进制 double 做散列；
3. **受控旁路：** 仅在 FreeRenderFPS 导出任务中旁路最终帧/合成缓存，同时保留可安全复用的媒体解码缓存；
4. **精确失效：** 每次 subframe 前失效与场景时间有关的缓存。当前尚不知道完整依赖图，不能粗暴全局清空。

推荐优先寻找“渲染任务对象 + 缓存键构造”交点，而不是在每个缓存层做零散补丁。媒体缓存可按源媒体时间继续复用，但对象、效果和合成缓存必须证明键包含 subframe 或被安全隔离。

## Phase 5 判定

- 对“两个整数帧之间能否产生不同状态”：成功。
- 对“同一整数请求能否用不同 double 重复求值”：失败，已定位为求值入口之前的缓存短路。
- 对“所有缓存是否支持 arbitrary subframe”：尚未证明，不能宣称成功。
