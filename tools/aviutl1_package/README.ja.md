# AviUtl 1.x FreeRenderFPS v1.0.1

AviUtl 1.10 + ExEdit 0.92 用の Win32 ビルドです。x264guiEx のエンコード、
音声、mux、設定、プリセット経路を再利用し、ExEdit のタイムライン評価境界で
要求されたサブフレーム時刻を注入します。フレーム複製、フレーム削除、FPS
メタデータだけの変更、後処理トランスコードではありません。

## v1.0.1 の変更点

- リリースビルドは、フレームごとの診断ログ `freerenderfps_aviutl1_probe.log`
  を書き出さなくなりました。診断トレースはローカルの診断ビルドにのみ含まれます。
- FreeRenderFPS の有効中は、ホストのコピーフレームフラグを無視します。
  新しいフレームの代わりに前の画像が再送されることはありません。
- フックの導入と削除の前後でのスレッド停止をより安全にしました。どのスレッドを
  停止する前にも、スレッド ID を先に収集します。書き換え対象のバイト列の内側で
  スレッドが実行中の場合は、（再試行後に）パッチを適用しません。フックを安全に
  復元できない場合は、パススルーの detour を残します。
- キャッシュ退避用のレンダリング結果を再利用します。これにより 30 → 60 では、
  出力フレームごとに 1.5 回ではなく 1 回のレンダリングで済みます。
- パッケージには既定の `.conf` を含みません。

## インストール

1. AviUtl を終了します。
2. `AviUtl1-FreeRenderFPS-v1.0.1-portable.zip` を AviUtl 1.10 のルートへ
   展開し、`Plugins` の構成を保ちます。
3. `Plugins` 内で `x264guiEx-FreeRenderFPS.auo` と同名の 3 個の INI を
   一緒に置きます。
4. 対応する x264、FFmpeg、L-SMASH runtime は `Plugins\exe_files` にあります。
5. AviUtl を再起動し、`x264guiEx FreeRenderFPS` を選び、`Free Render FPS`
   を有効にして目標 FPS を指定します。

AUO を古い `x264guiEx-FreeFPS.auo` に変更したり、古い同名機能のコピーを
同時に読み込ませたりしないでください。`.conf` はユーザー状態のため、
クリーンパッケージには含めていません。

## 検証

実際の `30 → 60 FPS` 出力は 60/1、300 映像フレーム、5.000000 秒です。
音声は 44.1 kHz ステレオ AAC、217 フレーム、同じ 5.000000 秒です。
デコード済みハッシュは 299 個が固有で、唯一の隣接重複はプロジェクト末端の
境界です。連続動作部分は 30 FPS のフレーム対ではありません。測定値は
`Docs\LEGACY_AVIUTL1_VALIDATION.md` にあります。

上記の 30 → 60 の測定は v1.0.0 で行いました。v1.0.1 のバイナリは、AviUtl 1.10
と ExEdit 0.92 で再検証する必要があります。

## 対応範囲

プラグインは x86 AviUtl 1.x 用で、公式 AviUtl 1.10 と ExEdit 0.92 に固定
されています。外部エンコーダーと muxer は子プロセスとして動作するため、
64 bit Windows では同梱の x64 runtime を使用できます。AviUtl ホスト本体は
含まれていません。

詳細は `Docs\KNOWN_LIMITATIONS.md` と `LEGACY_AVIUTL1_SETUP.md` を参照してください。
